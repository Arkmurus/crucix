# i18n scope decision — 2026-05-20 (R-F754)

## Decision

**en-only at Oct 2026 launch.** No `ngx-translate` (or equivalent)
wiring before launch. Multi-lingual support (FR/PT/AR/others)
revisits in Q1 2027 if-and-only-if a Francophone / Lusophone /
Arabic-speaking design partner is signed and asks.

Operator confirmed 2026-05-20 in response to the post-audit
"i18n scope" question.

## What changed in this commit

Deleted the four unused locale stub files:

  - `locales/en.json`  (≈13 KB, 0 imports)
  - `locales/fr.json`  (≈13 KB, 0 imports)
  - `locales/pt.json`  (≈14 KB, 0 imports)
  - `locales/ar.json`  (≈14 KB, 0 imports)

These shipped in the initial Angular scaffold but were never wired
into the build. The 2026-05-20 audit (frontend section) flagged them
as dead code: ~54 KB of translation pairs that no component or
service ever loaded. Frontend text is hardcoded in `.ts` files
throughout `frontend/src/app/`.

The only locale-shaped reference in the codebase is at
`frontend/src/app/app.module.ts:4`:

```ts
import localeEnGB from '@angular/common/locales/en-GB';
```

That is Angular's BUILT-IN en-GB locale data for date/currency
formatting (kept — Angular needs it). It has nothing to do with the
deleted JSON files.

## Why this is honest

The audit's question was not "is i18n a good idea?" — it was "are
you actually shipping i18n in October?" The locale JSON files sat
in the repo for months giving any reader the impression that
multi-lingual was a near-term plan. Deleting them aligns the code
with the operational truth: we ship en-only, and we're being
explicit about it.

Re-adding i18n is not blocked by this commit. A future R-number can
re-scaffold under a tracked locales/ directory, wire ngx-translate
properly, and update the build pipeline. That is a 1-sprint task.
Doing it pre-emptively against an empty translation backlog is not.

## Pickup-list note

If a multi-lingual design partner asks, the i18n cost estimate is:

| Component                            | Effort        |
|--------------------------------------|---------------|
| ngx-translate wiring + HttpLoader    | 2 days        |
| Audit every component for hardcoded strings → wrap in `{{ 'KEY' \| translate }}` | 5 days        |
| Build & ship one full translation set (the launch language)     | 3 days        |
| RTL CSS for Arabic (if AR is launch) | +3 days       |
| QA pass (string overflow, currency, dates)                     | 2 days        |

So ~10-15 dev-days to ship FR or PT as a second launch language;
+3 days if AR is in scope. None of this work is started.

## R-F754 deploy footprint

Frontend dist (`frontend/dist/crucix-admin/`) is built artefact and
already does not reference the deleted JSONs. Express server.mjs
does not serve `locales/*` directly (no static route). seenode pulls
from main and rebuilds — no manual deploy action required.

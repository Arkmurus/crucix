## SEV-0 — act today

### 0.1 Unauthenticated path traversal leaks the internal brain to the public internet
`server.mjs:1779-1796` · **REPRODUCED LIVE**

```
GET https://imaria.io/api/aria/cost/monthly/status                        → 401
GET https://imaria.io/api/vetting-portal/..%2f..%2fapi%2faria%2fcost%2fmonthly%2fstatus → 200
{"month":"2026-08","spent_usd":21.483923,"cap_usd":300,...}
```

The vetting-portal proxy is deliberately unauthenticated (correct — applicants and referees have no account, per the R-F3180 comment at `:1759`) and is mounted *before* the authenticated `/api/aria` catch-all. Express percent-decodes `req.params[0]`, so `%2f` → `/`; the `..` segments survive into the template at `:1786` and WHATWG URL parsing collapses them. `_ariaHeaders()` then attaches the brain service token to the rewritten request.

Every web-tier control — `requireAuth`, the infra-role gate, `pinNonAdminUserId` — is bypassed in one request. What still protects tenant data is only the brain's own `_OPERATOR_ONLY_RE` and `user_id` scoping, which is why `dd/reports` returned empty rather than full. That is a backstop, not a boundary.

The same class was fixed 40 lines earlier for operator pages (`isDoubleEncodedPath`, `server.mjs:1737`). That normaliser was never applied here.

**Fix:** reject any suffix containing `%`, a `.`/`..` segment, or a leading `/`; or rebuild the upstream path per-segment with `encodeURIComponent`. Needs an aria-web deploy.

Structural cause: **there is no executor cap anywhere** (`grep set_default_executor` → zero hits), so all 328 `asyncio.to_thread` sites share CPython's default pool sized `min(32, os.cpu_count()+4)` — and on Fly `os.cpu_count()` reports the *host*, not the machine's share. `redis_store.py:282,341` puts **every** `get_json`/`set_json` on that pool regardless of payload size. `aria_engine.py:1831` creates a **new** `ThreadPoolExecutor(max_workers=6)` per chat turn and shuts it down with `wait=False, cancel_futures=True`, deliberately abandoning any hung worker — and `concurrent.futures` threads are non-daemon, so an abandoned worker lives until its call returns. Live `pool_workers` was observed climbing 9 → 11 → 13 across 35 minutes; stall count rose 10 → 15 over 25 minutes (~12/hour).

Separately and independently **measured**: `wiring_monitor.py:69-104` `audit_wire_balance` globs and `ast.parse`s the entire `intel/` package — 390 files, 11.4 MB — **on the event loop**, hourly (`main.py:4360-4367`). Measured at **2.71s** of pure CPU locally; under this GIL contention it lands in the 5-8s band. Its exception handler at `:748-750` logs ERROR, which is itself a gate #3 resetter.

Also live: `state_store.get(crucix:audit:head_hash) timed out after 5s … Returning None` — a `None` on the audit chain head. That is not benign: `audit_log.py:218-225` `_read_head_hash` reads non-strict and its `except` returns `_GENESIS_HASH`, so `record()` writes a new head — **the evidentiary hash chain silently restarts from genesis on a transient read blip**, with no signal.

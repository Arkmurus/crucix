2. THE TWELVE INVARIANTS — the rules of the codebase
Break one of these and the PR is wrong even if it works.
1. The Python brain is authoritative for intelligence state. New reasoning lives in
Python, not Node.
2. The web tier is authoritative for browser identity and coarse role/quota enforcement.
3. Object ownership is re-checked at the authoritative service. The edge is not a
substitute for object-level checks.
4. Channel adapters never become reasoning brains.
5. Every user-visible action reports success AND failure. Delivery is separate from
generation — a generated answer is not a delivered answer.
6. Domain code uses the shared abstractions (state store, RAG store, model factory,
brain wiring) — never raw DB connections or vendor SDKs.
7. Facts and reports retain provenance. Absence of evidence is never a negative
finding.
8. Unknown or unmeasurable state is never converted into success.
9. Background work is idempotent, lease-aware, restart-safe, non-blocking.
10. No new store without ownership, retention, erasure, backup, and recovery rules.
11. Streaming and non-streaming paths keep behavioral parity — any
safety/audit/learning hook is applied to both.
12. A deployment is complete only when the live matches the intended
build_rev
commit. A green image build proves nothing.

checks → persist → respond or async job → normalized back up the chain. Sync and
streaming are separate entry paths (invariant 11).
WhatsApp: user → aria-wa (authenticate binding, dedupe, normalize) → brain with
→ immediate answer or async → brain callback → aria-wa sends → aria-
request_id job_id

optional (invariant 5).
Due diligence: an orchestrated multi-layer workflow (identity → corporate/ownership →
sanctions/PEP → adverse info → commercial/jurisdictional → verification → synthesis →
report), where every layer emits structured output + provenance, layer failures are explicit
and feed completeness/confidence, reports are stored by run/case ID, and rendering is
downstream of structured evidence, never the data model. Read the live orchestrator +
tests for the current layer set — historical docs contain stale layer counts.

Brain wiring ( via / ): the single

gateway through which outcomes become observable and learnable — signal

Ownership: intel owns sessions/cases/evidence/RAG/ledgers; web owns

7. Models
All Python model access goes through . Domain modules
aria_service/llm/factory.py
never import vendor SDKs. The layer guarantees provider-neutral contracts, env-driven
config, bounded timeouts, classified failures, cost/latency metering, retrieval-before-
generation for knowledge tasks, transparent fallbacks, and response verification before
success is reported. Node adapters under exist for Node-owned features only —
lib/llm/
new reasoning goes in Python (invariant 1).
8. Security rules for every PR
Public routes are explicitly registered; everything else requires a session; privileged
mutations require admin/infra roles; internal calls use the internal Bearer.
User-scoped identifiers are pinned/checked at the edge and the brain.
Route-specific body/upload limits at Express; document text sanitized before RAG
ingestion; URLs and external content are untrusted; CLI output passes redaction.
Secrets live in runtime env / Fly secrets — never in the repo, browser bundles, logs, or
diagrams. Internal URLs are not secrets; tokens and provider credentials are.
Any new store must declare: owner, retention class + legal basis, subject
lookup/erasure, backup/recovery, provenance/correction semantics, and whether the
data may enter model context or training exports (invariant 10).
9. Recipes (follow exactly)
New FastAPI capability: domain logic in its package (not , not the handler) →
main.py
verify signatures/sync-async → typed request/response models → wire success AND
failure before the happy path → use state-store + factory abstractions → preserve
provenance and ownership → register in the right router → explicit edge proxy route only if
special auth/transformation is needed (else validate the catch-all) → tests including empty,
malformed, provider-failure, store-failure.
New data source: narrow adapter, normalized result contract → record source identity,
retrieval time, jurisdiction, rights, credibility tier → distinguish no-match / unavailable /
rate-limited / parse-failed / unauthorized → wire both outcomes → only validated content
enters RAG → fixtures for normal/empty/malformed/changed upstream → register health +
freshness.
New channel: transport/device state in its own adapter service → normalize inbound to the
brain contract with user identity + request ID → async completion for slow work → dedupe
retries and callbacks → report actual delivery outcome → expose health, binding state,
failure diagnostics.
New model provider: implement the interface under → register in (no
llm/ factory.py
direct imports) → normalize timeout/auth/quota/safety/malformed failures → metering +
provider identity in traces → test selection, success, failure, fallback through the factory.
New background loop: one-shot vs recurring → singleton/leader lease → idempotent,
restart-safe, bounded shutdown → capability test that drives the real loop body → load- and
latency-aware (loops share resources with interactive traffic).
